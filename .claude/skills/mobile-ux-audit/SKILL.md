# 移动端 UX 审计 Skill

## 何时调用

- 用户反馈"移动端体验差"
- 计划改造某个页面的移动端布局前
- 新页面合并前的移动端验收
- 整体对标氚云/钉钉移动端能力时

## 审计基准

- **目标设备宽度**：375px（iPhone 标准）+ 414px（大屏）双断点抽查
- **目标场景**：钉钉内嵌 H5（无系统级返回栏，依赖页面自己处理返回）
- **目标延迟**：移动 4G 网络，首屏可用 < 2s
- **目标交互**：单手操作、拇指热区在屏幕下半部

## 审计 8 维

逐项过，每项记录"通过 / 待改 / 严重"：

### 1. 布局可用性

- 页面在 375px 下是否横向溢出？（任何 `overflow-x: auto` 之外的横滑都是问题）
- 表格类页面是否已转为 `MobileCardList` 形态？
- 表单是否单列纵向？label 是否在输入框上方？
- 模态框（DetailModal、表单弹窗）在 375px 下是否撑满 / 留出关闭区？

### 2. 触摸热区

- 按钮、链接最小可点击区域是否 ≥ 44×44px？
- 列表项整行可点 vs 仅文字可点？整行优先。
- 删除/危险操作是否需要二次确认 + 离主操作有距离？

### 3. 输入体验

- 数字输入框是否 `inputMode="decimal"` / `numeric"`？
- 金额输入是否禁用了浏览器自动填充建议？
- 日期选择器是否用原生 `type="date"` 而非 PC 的下拉日历？
- 搜索框是否提供清除按钮？
- 多文件上传是否支持相册多选 / 拍照？

### 4. 加载与反馈

- 首屏是否有骨架屏 / Spinner？
- 提交按钮在请求中是否禁用并显示 loading？
- 上传进度是否可见（已有 `feat(upload): 第八批` 的进度条基础）？
- Toast / 错误提示是否在拇指可见区？

### 5. 导航与返回

- 顶部是否有清晰的返回入口（不依赖系统手势）？
- 页面间跳转是否保留来源参数（避免返回丢上下文）？
- 钉钉容器内是否处理了 `dd.biz.navigation.setLeft` 类适配？

### 6. 性能

- 首屏请求数？是否能合并？
- 列表是否分页 / 虚拟滚动？长列表（>50 项）滚动是否卡顿？
- 图片是否懒加载？是否有合理的占位图？
- bundle size 是否被这个页面拖大？

### 7. 钉钉内嵌兼容

- 是否检测了运行环境（钉钉 / 浏览器）？
- 钉钉签名免登链路是否在弱网下有降级？
- 调起钉钉原生能力（扫码、上传、定位）是否做了失败兜底？

### 8. 不破坏 PC

- 同一组件在桌面 ≥1024px 下是否仍然合理？
- 是否引入了"仅移动端"逻辑而漏了桌面分支？
- CSS 媒体查询的 min/max 是否和现有断点体系一致？

## 输出格式

```
【审计页面】<路径列表>
【整体评分】<可上线 / 需修 / 严重不可用>
【按 8 维度的问题清单】
  - 维度名 | 严重度 | 现象 | 建议改法
【优先级 P0/P1/P2 摘要】
【是否影响 PC 端】
```

## 必须遵守

- **不要直接改代码**。审计阶段只输出清单，由用户决定哪些进入实施。
- **不要建议引入新 UI 库**。沿用现有 antd / 项目内 `MobileCardList` 等基础。
- **不要破坏 PC 端**。任何建议必须考虑桌面侧不变。
- **不要碰 CLAUDE.md 第四节核心能力**的非 UI 部分（业务逻辑、API、权限）。

## 输出节制

- 单次审计单页，回复 ≤ 50 行
- 多页批量审计，每页一段，单段 ≤ 15 行
- 不要贴大段截图描述，用结构化语言
