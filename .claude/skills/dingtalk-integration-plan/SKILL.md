# 钉钉集成方案设计 Skill

## 何时调用

- 用户提出"钉钉待办不够"、"催办不灵"、"想做工作通知"等需求
- 评估某个业务流程是否值得接入钉钉原生能力
- 已有钉钉调用方式不满足，准备升级到新 API
- 对比"OA 审批" vs "工作通知" vs "待办" 三条路线该走哪条

## 现有基础（先读再说）

调用前必读：

- `lib/dingtalk.ts`：access_token 获取、签名、基础 client
- `lib/dingtalk-notify.ts`：工作通知现有封装
- `app/api/auth/*`：免登链路
- 已有相关提交：
  - `eac5fda 第五批：钉钉接口/版本号/区域切换加固`
  - `2b942db fix attachment open and urge notification feedback`

任何方案都建立在这些已有代码之上，**不要平行另起一套**。

## 钉钉能力地图（速查）

| 能力 | 用途 | 关键 API | 限制 |
|------|------|----------|------|
| **工作通知** | 强提醒，会响铃 | `topapi/message/corpconversation/asyncsend_v2` | 单日/单用户上限；过度使用会被钉钉降级 |
| **待办（DingTalk Todo）** | 在"待办"Tab 出现，可标记完成 | `v1.0/todo/users/{unionId}/tasks` | 需 unionId；finish/delete 由调用方维护 |
| **OA 审批** | 全套钉钉审批流（钉钉控件） | `topapi/processinstance/*` | 表单与本系统重复，慎用 |
| **群机器人** | 群内通知，无定向 | webhook | 不能定向到人 |
| **DING 消息** | 老式强提醒 | `topapi/message/corpmessage/send` | 已弱化，不推荐新接入 |
| **催办** | 在已发待办上重发提醒 | 待办 API + 工作通知组合 | 钉钉无原生"催办"接口，需自己组合 |

## 方案设计 5 步

### 1. 明确业务诉求

回答以下问题再动笔：

- 谁触发？（系统自动 / 操作人手动 / 定时任务）
- 通知谁？（审批人 / 申请人 / 抄送人 / 角色组）
- 什么级别？（强提醒响铃 / 静默提示 / 仅 Tab 红点）
- 用户响应路径？（点击 → 跳到本系统某页 / 留在钉钉内处理）
- 需要回写吗？（钉钉端完成 → 是否反向更新本系统）

### 2. 路线对比

至少给出 2 条路线 + tradeoff，让用户选：

```
方案 A：纯工作通知
  优点：实现快、链路短、已有封装可复用
  缺点：消息会被淹没、无"待办"语义、催办靠重发

方案 B：待办 + 工作通知组合
  优点：在钉钉"待办"Tab 沉淀、可标记完成、催办语义清晰
  缺点：需维护 unionId、需 lifecycle（创建/完成/撤销）、API 调用量翻倍

方案 C：OA 审批
  优点：钉钉原生审批控件
  缺点：和本系统审批流冲突，不建议
```

### 3. 链路绘制

画出从业务事件 → 钉钉 → 用户 → 回写本系统的完整链路。标注每一步的：

- 触发时机
- 调用 API
- 失败兜底
- 限流/重试策略

### 4. 风险清点

至少检查这 7 项：

- access_token 缓存是否会被并发刷爆
- unionId 映射是否完备（所有目标用户都能拿到）
- 钉钉 API 限流是否会触顶
- 用户拒收 / 退出企业后的兜底
- 网络抖动时是否会重发同一条
- 审批人变更后已发待办是否要撤销
- 系统侧的"已通知"状态如何沉淀（避免重复通知）

### 5. 输出方案文档

回复格式：

```
【业务场景】
【推荐路线】
【备选路线】
【完整链路】
【新增/改动文件预估】
【风险与兜底】
【实施分阶段建议】
【需用户确认事项】
```

## 必须遵守

- **不直接改代码**。Skill 产出方案，落地走用户审过的独立任务。
- **不引入新的钉钉 SDK / 第三方钉钉库**。沿用 `lib/dingtalk.ts` 既有 client。
- **不要改 access_token 缓存模型**，除非用户明确同意。
- **不要批量给所有人发测试通知**。任何测试至少先在用户自己的账号上跑一轮。
- **不要把 corpId / appKey / appSecret 写进回复**，引用时只用变量名。

## 输出节制

- 方案设计回复 ≤ 100 行
- 不要展开 API 文档全文，只列关键字段
- tradeoff 用表格或 2-3 行内描述
